# 一盤棋

一張黑底的粉筆素描:只有一個棋盤。照真正的規則下,你執白,黑方有個看不見的對手。這個網站不說自己是誰,也不解釋任何東西。

用 Vite、TypeScript 和 [Three.js](https://threejs.org/) 製作。棋盤與棋子全部是程式生成的切面模型,沒有載入任何模型檔或圖片;粉筆素描的樣子是即時的後製效果,不是貼圖。

> 目前所有文字(碎片、物件、痕跡、最後一頁)都是**範例內容**,請依照下方「改成你自己的內容」替換。

## 玩法

畫面上只有棋盤、右上角的語言與音效開關,和左下角重新開局的按鈕。沒有名字,沒有說明。

- **照規則下。** 王車易位、吃過路兵、升變(自動升后)、將軍、將死、逼和,以及和棋(重複局面、五十步、子力不足)都有。拖曳棋子,或先點棋子再點目標格;舉起棋子時,能去的格子會標出來。走不得的地方,棋子會彈回原位。
- **你執白,黑方自己應手。** 你走完,它停一下才回:它會看幾步之後的局面,開局有一小本棋譜,偶爾也會走進陷阱。
- **一盤棋結束之後**(將死、逼和、和棋),棋盤會自己擦乾淨重新開始。
- **五扇門。** 每一顆棋子(兵、馬、象、車、后)對應一頁。把那顆棋子走到屬於它的那一格,那一頁就會打開。是哪一格、畫面上沒有字,它只對帶著光的人現身:滑鼠、手指或鍵盤游標靠近的地方,暗處會浮出東西。
- 前四扇門都打開之後,棋盤上會畫出幾條線。第五扇門在哪裡,它們知道。
- 贏下一盤棋(將死黑方)也能打開門:是哪一顆棋子送出最後一擊,就打開哪一頁。
- 打開過的頁面會在畫面上方留下一個符號,點它可以再打開。還沒打開的頁面不會出現在畫面上,內容在打開之後才會下載(每一頁是獨立的 chunk)。
- 進度存在瀏覽器的 localStorage,重新整理不會消失。
- 一共藏了 19 個彩蛋:特別的棋、鍵盤指令、終端機(按 `` ` ``)……進度只在最後一頁看得到。

操作:滑鼠或觸控拖曳棋子,或先點棋子再點目標格;拖曳背景旋轉、滾輪或雙指縮放。鍵盤:方向鍵移動游標、Enter 或空白鍵拿起/放下、`Esc` 取消或關閉頁面。

答案寫在 `src/game/locks.ts`。想換掉格子的話改那裡,`npm test` 會確認每一格都還走得到(對隨機走子的對手、也對真正的對手),而且最後一格仍然看得見另外四格。這只是個小遊戲,不是安全機制:任何人都能讀原始碼。

## 畫風怎麼運作

場景先用一般的燈光照亮(顏色全是灰階,**亮度就是「要多少粉筆」**),再由 `src/three/sketch/` 重畫成黑底上的粉筆素描:

1. 把場景畫三次:受光的畫面、法線與深度。
2. 合成時,深度或表面方向突然改變的地方畫粉筆線(輪廓畫得重,切面之間的邊畫得輕),線會輕微抖動、補畫一次,像手畫的。
3. 越亮的地方排線越多:先是一個方向,最亮處才交叉,每一筆各自決定要不要出現,所以排線是一筆一筆變密、而不是淡入。棋盤(朝上的面)與棋子(直立的面)的排線角度不同,兩者不會糊在一起。陰影處什麼都不畫,就是黑底本身。
4. 有顏色的東西(游標、選取框、將殺的光環)被當成橘色的標記筆,疊在上面。
5. 燈光落在棋盤中央,往四周漸暗,並且會稍微跟著滑鼠偏移;畫面開頭是從中央一筆一筆「顯影」出來的。
6. 輔助線(`guides.ts`):棋盤外的兩圈圓與刻度、棋盤邊線與對角線的延長、定位用的十字,都是自己會抖的線,開頁時一筆一筆畫出來。它們用場景的深度比對,所以會被棋盤擋住。
7. 暗處的東西(`whispers.ts`):每扇門有一顆棋子的線框輪廓,站在屬於它的格子上,平常看不見;燈(滑鼠、手指、鍵盤游標)靠近時才浮出來,偶爾也自己喘一口氣。打開的門在格子上留一個橘色的圈;前四扇門都開了,就畫出通向第五格的線。

想調畫風,改 `src/three/sketch/pipeline.ts` 裡的 `DEFAULT_LOOK`(紙色、粉筆色、排線疏密與各方向出現的亮度、輪廓粗細)與 `src/three/lighting.ts` 的燈光。`npm run dev` 之後打開 `/lab.html` 是棋子實驗頁,黑白兩排並排、可用 `window.__lab` 移動相機;`window.__lab.sketch.setDebug(true)` 會顯示場景實際的亮度,方便調燈光。

字型是 [Caveat](https://fonts.google.com/specimen/Caveat)(標題)與[霞鶩文楷 TC](https://fonts.google.com/specimen/LXGW+WenKai+TC)(內文),從 Google Fonts 非阻塞載入;沒載入時退回系統字型。

## 棋子的比例

照真實的 Staunton 比例做(比賽用的王約 1.7 個格子高,底座直徑約身高的 40%),單位是棋盤的一格:

| 棋子 | 高度 | 底座直徑 |
| --- | --- | --- |
| 王 | 1.78 | 0.72 |
| 后 | 1.55 | 0.68 |
| 象 | 1.44 | 0.66 |
| 馬 | 1.35 | 0.66 |
| 車 | 1.12 | 0.66 |
| 兵 | 0.96 | 0.58 |

形狀在 `src/three/pieces/`:`toolkit.ts` 的 `turnFacet` 把一圈圈的環旋轉成切面(相鄰兩環錯開半格,面就會變成菱形,像切割過的石頭),`staunton.ts` 是王后象車兵,`knight.ts` 是馬。`tests/pieces.test.ts` 會檢查這些比例沒有跑掉。

## 對手

`src/chess/` 是一個完整的規則引擎(`rules.ts`,用標準的 perft 節點數驗證過,見 `tests/rules.test.ts`)。黑方由 `search.ts` 下:alpha-beta 搜尋、吃子後的靜態搜尋、一張簡單的子力與位置評估表,每次最多看約三萬個局面,所以它很快、也有可能犯錯。`book.ts` 是它開局時的棋譜,其中兩條是故意設的陷阱。想讓它強一點或弱一點,改 `search()` 的 `depth`、`nodes` 與 `margin`。

## 開發

需要 Node.js 22.12 以上。

```bash
npm install
npm run dev        # 開發伺服器
npm test           # 單元測試
npm run typecheck  # 型別檢查
npm run build      # 正式建置到 dist/
npm run preview    # 預覽建置結果
```

## 部署到 GitHub Pages

1. 到 repo 的 **Settings → Pages**,把 **Source** 設成 **GitHub Actions**(只要做一次)。
2. 把程式推到 repo 的**預設分支**(一般是 `main`),`.github/workflows/deploy.yml` 會跑型別檢查、測試、建置,然後部署。如果程式早就推上去了、只是 Pages 還沒打開,到 **Actions** 分頁按 **Run workflow** 手動跑一次(或對失敗的那次按 **Re-run all jobs**)。
3. 網址會是 `https://<帳號>.github.io/<repo 名稱>/`。

這是 project site,資源路徑需要 `/<repo 名稱>/` 前綴,workflow 已經用 `BASE_PATH` 帶進去(分享預覽圖用的 `SITE_URL` 也是)。如果你用自訂網域,或 repo 名稱是 `<帳號>.github.io`,請在 workflow 裡把 `BASE_PATH` 改成 `/`,並把 `SITE_URL` 換成你的網址。

其他分支與 PR 只會跑檢查、不會部署。之後如果把預設分支改名(例如改成 `main`),記得到 **Settings → Environments → github-pages** 確認允許部署的分支也跟著改。

## 專案結構

```
src/
  chess/     規則引擎(合法走法、易位、過路兵、升變、將死與和棋)、黑方的搜尋與棋譜(純 TypeScript,有測試)
  three/     場景:棋盤、棋子模型(pieces/)、相機、輸入、特效、暗處才看得見的幽靈(whispers.ts)
    sketch/  粉筆素描:後製管線與著色器、輔助線、飄浮的粉筆灰
  game/      遊戲流程:走子動畫與判定、五扇門(locks.ts)、彩蛋、終端機指令、按鍵序列
  content/   各頁的內容(打開後才動態載入)
  ui/        HTML 介面:小圓鈕、符號列、側邊面板、終端機、提示
  i18n/      繁中與英文字典
  state/     進度存檔
tests/       Vitest
```

## 注意

- 解鎖是純前端的小遊戲,不是安全機制:頁面內容是公開的靜態檔案,只是不會在一開始就下載。
- 分享連結時的預覽圖是 `public/og.png`(1200×630),目前拍的是範例內容的畫面。改完自己的內容後,請重拍一張換掉。預覽圖需要完整網址,所以只有在建置時有設定 `SITE_URL`(workflow 會自動帶入)才會寫進 HTML。
- 瀏覽器不支援 WebGL 時會顯示後備頁面,只有一句話與聯絡方式。
- 畫面是逐像素重畫的,高解析度螢幕上如果持續掉幀,繪製解析度會自己調低。
